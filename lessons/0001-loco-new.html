Loco 速学 · 第 1 课 · Loco 1.2.0 · 命令速查

起一个 Loco 项目并跑起来

目标：一条命令生成项目，一条命令启动，用 curl 拿到 {"ok":true}。

1. 先知道两件事

Loco 就是 axum，加上一层预先做好的决定。路由、提取器、中间件都是你学过的 axum 0.8 那一套；Loco 替你把 main()、共享状态（AppContext，相当于你自己写的 State 结构体）、配置、日志、数据库都接好了。Rails 的核心思路叫“约定优于配置”：文件放在约定的位置、用生成器生成，框架就知道怎么接线，你不用手写装配代码。 出处：Coming from Axum

有两个命令行，别搞混。

命令是什么什么时候用
loco独立的项目生成器，cargo install loco 装一次只用来 loco new 建新项目
cargo loco不是真的 cargo 子命令，是生成项目里 .cargo/config.toml 的别名 loco = "run --"，实际运行你项目自己的二进制启动、迁移、生成代码……项目里的一切日常操作

出处：CLI reference、Your First App；别名已在生成的项目里核对。

2. 动手

前提：Rust stable ≥ 1.94（Loco 的 MSRV，见 Cargo.toml）。我这边是 1.99.1。

① 装生成器（约 30 秒） 
cargo install loco
loco --version
   Installed package `loco v1.2.0` (executable `loco`)
loco 1.2.0
② 生成项目（不到 1 秒） 
loco new --name admin_api --db sqlite --bg async --assets none
🚂 Loco app generated successfully in:
/workspace/teaching/loco-rs/playground/admin_api

四个参数都给了，向导就不再提问，结果可复现：

  • --db sqlite：数据库是本地一个文件，不用装 Postgres。选了数据库，项目自带一整套用户注册/登录接口（/api/auth/*），后台管理正好要用。
  • --bg async：后台任务在同一进程里用 tokio 跑，不需要 Redis。
  • --assets none：不生成页面，纯 JSON API。

为什么不是“选个 REST API 模板”：交互菜单里确实有 “Rest API (with DB and user auth)”，但命令行没有 --template 参数；上面这组参数的效果就是带数据库和用户鉴权的 REST API。出处：CLI reference §1.2–1.4

③ 启动（第一次要编译，耐心等） 
cd admin_api
cargo loco start
    Finished `dev` profile [unoptimized + debuginfo] target(s) ...
     Running `target/debug/admin_api-cli start`
 INFO loco_rs::db::migrate: auto migrating
 INFO sea_orm_migration::migrator::exec: Migration 'm20220101_000001_users' has been applied
 INFO loco_rs::controller::app_routes: [GET] /_ping
 ...
environment: development
   database: automigrate
     logger: debug
compilation: debug
      modes: server

listening on http://localhost:5150

注意 Running `target/debug/admin_api-cli start`——这就证明了 cargo loco 只是在跑你自己的程序。启动时它还自动执行了数据库迁移，建出了 users 表和 admin_api_development.sqlite 文件。

首次编译：我这台 8 核机器 cargo build 用了 55 秒，编译了 446 个 crate，target/ 占 2.7 GB。核数少的机器几分钟很正常。之后改代码再启动只要零点几秒到几秒。
④ 另开一个终端，打内置接口 
curl -i localhost:5150/_ping
HTTP/1.1 200 OK
content-type: application/json
x-request-id: 407930b9-fb63-45c9-a3ca-093f11faf943
x-powered-by: loco.rs
content-length: 11

{"ok":true}
curl localhost:5150/_health
curl localhost:5150/_readiness
{"ok":true}
{"ok":true}

这三个是 src/app.rs 里 AppRoutes::with_default_routes() 挂上的监控接口，一行代码没写就有。响应头里的 x-request-id、x-powered-by 是默认中间件加的——就是你学过的 axum 中间件，只是 Loco 用配置开关。

⑤ 停服务

回到跑服务的终端按 Ctrl+C。端口被占用时可以换端口：PORT=5151 cargo loco start（生成的 config/development.yaml 里写了这个用法，我试过可用）。

文档和实际不一致处（以实际为准）
  • 教程 Your First App 结尾说内置接口有 /api，实测 curl localhost:5150/api 返回 404。内置的是 /_ping、/_health、/_readiness。
  • 教程说启动后显示 listening on port 5150，1.2.0 实际显示 listening on http://localhost:5150。
  • CHANGELOG 顶部的 Unreleased 段还没发布，看到的改动在 1.2.0 里不一定有。

3. 生成了什么（只点名，下一课展开）

顶层一句话
src/你的代码：app.rs、controllers/、models/、dtos/ 等
config/各环境的 YAML 配置
migration/数据库迁移（独立的 crate）
tests/请求测试、模型测试
examples/playground 小程序
.cargo/cargo loco 别名所在
.github/、.claude/、AGENTS.mdCI 配置，以及给编程助手看的说明

启动后还会多出 target/、Cargo.lock 和 admin_api_development.sqlite。

5. 练习

  1. 在你自己的电脑上从 cargo install loco 开始，把第 2 节跑一遍。
  2. 把 curl -i localhost:5150/_ping 的完整输出贴回给我，顺便告诉我首次编译用了多久。
  3. 停掉服务后，在项目目录执行 cargo loco routes，数一数 /api/auth 下有几个接口。
  4. 明天开始下一课前，先不看本课，凭记忆写出那条 loco new 命令（四个参数）。
