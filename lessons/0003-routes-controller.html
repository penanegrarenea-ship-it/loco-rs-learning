手写 controller 并注册路由

目标：给后台加一个 GET /api/admin/stats/{section}?limit=2，返回写死的 JSON，带一个 Path 参数和一个 Query 参数。不碰数据库。

1. 先知道三件事

controller = 一个文件 + 一个 pub fn routes()。上一课你看到 auth.rs 就是这样。新 controller 要生效，还得在 controllers\mod.rs 里 pub mod、在 app.rs 里 add_route。生成器 cargo loco generate controller 把这几处一次改好——Rails 的习惯是“先生成，再改”，因为 Rust 没有自动加载，手工接线最容易漏。 出处：Add a controller

format::json(v) 就是 Loco 版的 Json(v)。1.2.0 源码 src/controller/format.rs：

pub fn json<T: Serialize>(t: T) -> Result<Response> {
    render().json(t)
}

它序列化后设 content-type: application/json；源码注释写明“Mirrors axum::Json's behavior”——序列化失败时和 axum::Json 一样回 500 纯文本，而不是返回 Err。区别只在类型：axum 里你写 -> Json<T> 或 impl IntoResponse，Loco 惯例统一写 -> Result<Response>，这样 handler 里能直接用 ? 返回 Loco 的错误。

axumLoco
async fn h() -> Json<Stats> { Json(stats) }async fn h() -> Result<Response> { format::json(stats) }

Path、Query 就是 axum 的。loco_rs::prelude::* 直接重新导出 axum::extract::{Path, Query, State, Form, Multipart}，用法、报错都和你学过的一样（下面会看到解析失败的 400）。 出处：1.2.0 源码 src/prelude.rs

③ 生成的 controller 原样 
#[debug_handler]
pub async fn index(State(_ctx): State<AppContext>) -> Result<Response> {
    format::empty()
}

#[debug_handler]
pub async fn ping(State(_ctx): State<AppContext>) -> Result<Response> {
    format::empty()
}

pub fn routes() -> Routes {
    Routes::new()
        .prefix("api/admins/")
        .add("/", get(index))
        .add("ping", get(ping))
}
注意前缀是 api/admins/：生成器把名字变成了复数（Rails 习惯，资源名用复数）。我们要的是 /api/admin，所以下一步手动改前缀。改完后旧地址 /api/admins/ping 就是 404。
④ 手改：前缀、让 ping 返回 JSON、加 stats handler

src\controllers\admin.rs 改完的全文：

#![allow(clippy::missing_errors_doc)]
#![allow(clippy::unnecessary_struct_initialization)]
#![allow(clippy::unused_async)]
use loco_rs::prelude::*;
use serde::{Deserialize, Serialize};

#[debug_handler]
pub async fn index(State(_ctx): State<AppContext>) -> Result<Response> {
    format::empty()
}

#[debug_handler]
pub async fn ping(State(_ctx): State<AppContext>) -> Result<Response> {
    format::json(serde_json::json!({ "pong": true }))
}

/// `?limit=2` —— 可选的查询参数
#[derive(Debug, Deserialize)]
pub struct StatsQuery {
    pub limit: Option<usize>,
}

#[derive(Debug, Serialize)]
pub struct StatItem {
    pub name: &'static str,
    pub value: u64,
}

#[derive(Debug, Serialize)]
pub struct StatsResponse {
    pub section: String,
    pub limit: usize,
    pub items: Vec<StatItem>,
}

/// GET /api/admin/stats/{section}?limit=2 —— 先返回写死的数据，下一课换成数据库
#[debug_handler]
pub async fn stats(
    Path(section): Path<String>,
    Query(q): Query<StatsQuery>,
) -> Result<Response> {
    let all = [
        ("total", 42),
        ("active_today", 7),
        ("pending_review", 3),
    ];
    let limit = q.limit.unwrap_or(all.len()).min(all.len());
    let items = all
        .iter()
        .take(limit)
        .map(|(name, value)| StatItem { name, value: *value })
        .collect();
    format::json(StatsResponse {
        section,
        limit,
        items,
    })
}

pub fn routes() -> Routes {
    Routes::new()
        .prefix("api/admin/")
        .add("/", get(index))
        .add("ping", get(ping))
        .add("stats/{section}", get(stats))
}

和 axum 比：Path(section): Path<String>、Query(q): Query<StatsQuery> 一字不差；路由占位符是 axum 0.8 的 {section}；get(stats) 是 axum 的 MethodRouter。这个 handler 用不到 AppContext，所以没写 State，和 axum 一样，不需要的 extractor 可以不写。

⑦ 故意出错，看框架怎么回 
curl.exe -s -i "http://localhost:5150/api/admin/stats/users?limit=abc"
HTTP/1.1 400 Bad Request
content-type: text/plain; charset=utf-8
……
Failed to deserialize query string: limit: invalid digit found in string
curl.exe -s -i -X POST http://localhost:5150/api/admin/ping
HTTP/1.1 405 Method Not Allowed
allow: GET,HEAD
content-length: 0
  • limit=abc：axum 的 Query 解析失败，handler 根本没执行，直接 400 纯文本。
  • POST 到只注册了 GET 的路径：axum 回 405，并带 allow 头。
  • 完全没注册的路径（如 /api/admins/ping、带尾斜杠的 /api/admin/）：404，响应体是一页 “Welcome to Loco!” HTML——这是默认开启的 fallback 中间件。纯 API 项目以后可以在 config\development.yaml 里关掉它。
⑧ 写 request 测试（可选，但推荐）

生成器已经建了 tests\requests\admin.rs。我把路径改成 /api/admin，并加了一个 stats 的测试。全文：

use admin_api::app::App;
use loco_rs::testing::prelude::*;
use serial_test::serial;

#[tokio::test]
#[serial]
async fn can_get_admins() {
    request::<App, _, _>(|request, _ctx| async move {
        let res = request.get("/api/admin").await;
        assert_eq!(res.status_code(), 200);

        // you can assert content like this:
        // assert_eq!(res.text(), "content");
    })
    .await;
}

#[tokio::test]
#[serial]
async fn can_call_ping() {
    request::<App, _, _>(|request, _ctx| async move {
        let res = request.get("/api/admin/ping").await;
        assert_eq!(res.status_code(), 200);
        assert_eq!(res.text(), r#"{"pong":true}"#);
    })
    .await;
}

#[tokio::test]
#[serial]
async fn can_get_stats_with_path_and_query() {
    request::<App, _, _>(|request, _ctx| async move {
        let res = request.get("/api/admin/stats/users?limit=2").await;
        assert_eq!(res.status_code(), 200);

        let body: serde_json::Value = res.json();
        assert_eq!(body["section"], "users");
        assert_eq!(body["limit"], 2);
        assert_eq!(body["items"].as_array().unwrap().len(), 2);
    })
    .await;
}

你在 axum 里用 oneshot 或 TestServer；这里 request::<App, _, _> 按 config\test.yaml 启动整个 App，回调里的 request 就是 axum_test::TestServer，所以 .get(...)、status_code()、text()、json() 都是 axum-test 的方法。

cargo test --test mod requests::admin
running 3 tests

所有集成测试都在一个测试目标 mod 里（tests\mod.rs），所以用 --test mod 加模块路径过滤。

文档和实际不一致处（以 1.2.0 实际为准）
  • Add a controller 的验证步骤写 curl -s localhost:5150/api/notes/（带尾斜杠）。实测带尾斜杠的 /api/admin/ 返回 404，只有 /api/admin 是 200。
  • 同一页写 cargo test --test requests_notes。实际没有这个测试目标：cargo test --test requests_admin 报 no test target named `requests_admin`，可用的只有 mod。
  • 文档没提生成器会把 controller 名变复数（admin → api/admins/）。
