scaffold：一条命令生成整套 RESTful CRUD

目标：给后台加“商品分类” category（name:string! description:text），一条 cargo loco generate scaffold 生成表、entity、DTO、controller 和路由，然后用 PowerShell 走一遍 增 / 查 / 改 / 删。

1. 先知道三件事

scaffold = 第 4 课的 model + 一个 CRUD controller + DTO。migration、entity、models\categories.rs、model 测试都和 generate model 一样，额外多出 src\controllers\categories.rs（5 个 handler + 路由）和 src\dtos\categories.rs（请求 / 响应结构体）。 出处：Generators & field types、Your First App §4

1.2.0 没有 --api 了。--help 里只有 --without-tz 和 --no-auth。生成器会看项目里有没有 frontend\src\routes.tsx：没有就只生成 JSON API（我们是 --assets none，正是这种）。老教程里的 --api 还能写，但什么都不做；--html/--htmx 会直接报错。 出处：1.2.0 源码 src/cli.rs warn_legacy_scaffold_kind

默认要登录。不加 --no-auth 时，每个 handler 都带 auth::JWT 提取器，匿名请求回 401。这课先加 --no-auth 专心看 CRUD，鉴权以后单独讲。

2. 动手（在 playground\admin_api 真跑过）

PowerShell 写法，在 admin_api\ 根目录执行，先 Ctrl+C 停服务、git commit 一下。我在 Linux 版 PowerShell 7 上跑，输出照实贴（日志行去掉了时间戳，路径显示为 /）。

④ 生成的 controller（节选，省掉了 create/remove，几处长行合成了一行） 
fn not_found(message: &str) -> Response {
    let error = ApiError { code: "not_found".to_string(), message: message.to_string(), details: None };
    (StatusCode::NOT_FOUND, Json(error)).into_response()
}

async fn list(
    State(ctx): State<AppContext>,
    Query(pagination): Query<query::PaginationQuery>,
) -> Result<Json<Page<CategoryDto>>> {
    let res = query::paginate(&ctx.db, Entity::find().order_by_asc(Column::Id), None, &pagination).await?;
    Ok(Json(Page::from_query(res)))
}

async fn get_one(State(ctx): State<AppContext>, Path(id): Path<i64>) -> Result<Response> {
    let Some(model) = Entity::find_by_id(id).one(&ctx.db).await? else {
        return Ok(not_found("category not found"));
    };
    Ok(Json(CategoryDto::from(model)).into_response())
}

async fn update(State(ctx): State<AppContext>, Path(id): Path<i64>, Json(params): Json<UpdateCategory>) -> Result<Response> {
    let Some(model) = Entity::find_by_id(id).one(&ctx.db).await? else {
        return Ok(not_found("category not found"));
    };
    let mut item = model.into_active_model();
    item.name = Set(params.name);
    item.description = Set(params.description);
    let item = item.update(&ctx.db).await?;
    Ok(Json(CategoryDto::from(item)).into_response())
}

pub fn routes() -> Routes {
    Routes::new()
        .prefix("/api/categories")
        .add("/", get(list))
        .add("/", post(create))
        .add("/{id}", get(get_one))
        .add("/{id}", put(update))
        .add("/{id}", delete(remove))
}
  • 404 怎么来的：每个带 {id} 的 handler 自己 find_by_id(...).one()，查不到就返回本文件的 not_found()：404 + ApiError JSON（src\dtos\common.rs）。没有 load_item 这种公共函数，三处各写一遍。
  • 有分页：?page= 和 ?page_size=，默认第 1 页、每页 25（源码 paginate/mod.rs），返回 {items, page, page_size, total_pages, total_items}。
  • 没有校验：CreateCategory 只是普通的 Deserialize 结构体。缺字段由 axum 的 Json 拒绝；name 传空字符串照样能存进去（下面实测）。
  • 没用到你的 model：它直接 use crate::models::_entities::categories::{ActiveModel, Entity}，绕过了 models\categories.rs。不过 models\categories.rs 里的 ActiveModelBehavior 是挂在同一个 ActiveModel 类型上的，所以 update 时自动刷新 updated_at 仍然生效。

DTO 和 axum 里你自己写的请求/响应结构体是一回事：Json(params): Json<CreateCategory> 就是 axum 的 Json 提取器。CategoryDto 带 ts_rs::TS，可以导出 TypeScript 类型给前端，暂时不用管。

⑦ 测试 
cargo test
test result: ok. 31 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 8.60s

比第 4 课多 1 条：生成的 models::categories::can_query_categories。接口测试要自己写（写法见第 3 课 ⑧）。

和 DDD 的关系：scaffold 生成的是“贫血” CRUD：controller 直接拿 entity 读写，没有任何业务规则，models\categories.rs 是空的。它是起点，不是成品。按 Loco 的 doctrine（胖 model、瘦 controller），以后“名称不能为空”“同名分类不能重复”这类规则写进 models\categories.rs，controller 只调用。下面的小任务就是第一步。
文档 / 旧教程和 1.2.0 实际不一致处
  • 1.0 之前的教程和博客写 generate scaffold … --api、--html、--htmx。1.2.0 的 --help 已经没有它们：--api 是隐藏的空操作，--html/--htmx 报错。现在的文档（Use generators）已经说明了这一点。
  • 网上常见的旧版 scaffold（如 0.16.0 的模板）生成 load_item、带 update() 方法的 Params 结构体、add handler 和 PATCH 路由。1.2.0（现在的模板）都没有：改成了 src\dtos\ 里的 CreateCategory/UpdateCategory，handler 叫 create，只有 PUT。
  • Use generators 说 scaffold 生成 “controller + routes + tests”，实际只有一条 model 测试，没有接口测试；Generators reference 写的 “a model test” 才准确。该页标的源码行号（cli.rs:268）在 1.2.0 已是第 279 行。

第 2 题参考答案（我在 playground 里实测过，先自己写再看）

src\models\categories.rs（顶部 use 改成 use loco_rs::prelude::*;，导出加 self）：

pub use super::_entities::categories::{self, ActiveModel, Entity, Model};
use loco_rs::prelude::*;

impl Entity {
    /// 后台分类列表的查询规则：`q` 非空时只要名称包含它的记录，按 id 排序。
    pub fn search(q: Option<&str>) -> sea_orm::Select<Self> {
        let select = Self::find().order_by_asc(categories::Column::Id);
        match q.map(str::trim).filter(|q| !q.is_empty()) {
            Some(q) => select.filter(categories::Column::Name.contains(q)),
            None => select,
        }
    }
}

src\controllers\categories.rs：

/// `?q=book` —— 可选的名称关键字
#[derive(Debug, serde::Deserialize)]
pub struct ListFilter {
    pub q: Option<String>,
}

async fn list(
    State(ctx): State<AppContext>,
    Query(pagination): Query<query::PaginationQuery>,
    Query(filter): Query<ListFilter>,
) -> Result<Json<Page<CategoryDto>>> {
    let res = query::paginate(&ctx.db, Entity::search(filter.q.as_deref()), None, &pagination).await?;
    Ok(Json(Page::from_query(res)))
}
