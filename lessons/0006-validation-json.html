输入校验和统一的 JSON 错误

目标：修好第 5 课留下的两个问题——name: "" 也能 201，缺字段只回笼统的 {"error":"Bad Request"}。给 category 的 create/update 加校验，失败时返回带字段名的 JSON 错误；顺带让响应只带需要的字段。

1. 先知道三件事

Loco 的主推做法：DTO 上 #[derive(Validate)] + 提取器 JsonValidateWithMessage。官方 Validate requests 列了 6 个提取器，都在 loco_rs::controller::extractor::validate，其中 JsonValidate 和 JsonValidateWithMessage 直接在 loco_rs::prelude 里。区别只有一个：

提取器校验失败时
JsonValidate<T>400 {"error":"Bad Request"}，看不出哪个字段错
JsonValidateWithMessage<T>400 {"errors":{"字段":[{code,message,params}]}}

后台要给前端显示“哪个字段错了”，所以用 WithMessage。源码 extractor/validate.rs 第 261–303 行：先用 axum 的 Json 解析，再调 validate()，失败转成 Error::Validation；controller/mod.rs 第 185 行把它变成 400 + {"errors":…}。

解析失败和校验失败是两回事。JSON 都解析不了（缺必填字段、语法错、没带 Content-Type），在校验之前就被 axum 拒绝，Loco 只保留 axum 的状态码，body 一律是 {"error":"Bad Request"}（controller/mod.rs 第 250 行）。这就是第 5 课 422/415 都写 “Bad Request” 的原因。下面用 #[serde(default)] 把“缺 name”也拉进校验。

格式校验放边界，业务规则放 model。“长度 1–50”只看这一个请求就能判断，放在 DTO 上；“名称不能和别的分类重复”要查数据库，是领域规则，放 models\categories.rs，返回 ModelError::EntityAlreadyExists，Loco 自动映射成 409（练习 3）。

其他做法一句话：model 层还有 Validatable trait（validation.rs），源码注释示例在 before_save 里调 self.validate()?——我实测这样会回 500（见文末不一致处），不推荐；bad_request("…") 返回 400 {"error":"Bad Request","description":"…"}，适合单条手写判断；format::render().status(…).json(…) 可以回任意状态码和结构。

② DTO 加校验：src\dtos\categories.rs 
use ts_rs::TS;
use validator::Validate;

#[derive(serde::Serialize, serde::Deserialize, TS, Validate)]
pub struct CreateCategory {
    /// 没传 name 时按 "" 处理，走字段级校验，而不是笼统的 422
    #[serde(default)]
    #[validate(length(min = 1, max = 50, message = "name must be 1-50 characters"))]
    pub name: String,
    #[validate(length(max = 200, message = "description must be at most 200 characters"))]
    pub description: Option<String>,
}
// UpdateCategory 同样加这两行 #[validate(...)] 和 #[serde(default)]
  • validator 已经在生成项目的 Cargo.toml 里（validator = { version = "0.20" }），不用再加依赖。
  • length 按字符数算，中文一个字算 1（validator 源码 chars().count()）。
  • Option<String> 是 None 时不检查，有值才检查长度。
  • 错误信息用英文：避免 Windows 控制台显示中文 JSON 时出现编码问题。

就这两行。JsonValidateWithMessage 在 loco_rs::prelude::* 里，不用另外 use。和 axum 比：它就是一个自定义 FromRequest，相当于你在 axum 里自己写 “先 Json 再 validate()” 的提取器。

④ 响应结构体只带需要的字段（view）

这个项目有两个放响应结构体的地方：src\views\（loco new 生成，里面是 auth 的 LoginResponse 等）和 src\dtos\（scaffold 生成，带 ts_rs::TS）。category 的响应结构体是 dtos\categories.rs 里的 CategoryDto，就改它：后台列表不需要时间戳，删掉 created_at/updated_at 两个字段和 From 里对应的两行：

#[derive(serde::Serialize, serde::Deserialize, TS)]
pub struct CategoryDto {
    #[ts(type = "number")]
    pub id: i64,
    pub name: String,
    pub description: Option<String>,
}

impl From<crate::models::_entities::categories::Model> for CategoryDto {
    fn from(m: crate::models::_entities::categories::Model) -> Self {
        Self { id: m.id, name: m.name, description: m.description }
    }
}

原理：响应里有什么字段，完全由你 Json(...) 的那个结构体决定；数据库 Model 不直接出门。顶部的 use sea_orm::prelude::DateTimeWithTimeZone; 不再用到，一起删掉。

⑥ 写一个 request 测试锁住它

新建 tests\requests\categories.rs，并在 tests\requests\mod.rs 末尾加 pub mod categories;：

use admin_api::app::App;
use loco_rs::testing::prelude::*;
use serial_test::serial;

#[tokio::test]
#[serial]
async fn create_rejects_empty_name_with_field_errors() {
    request::<App, _, _>(|request, _ctx| async move {
        let res = request
            .post("/api/categories")
            .json(&serde_json::json!({ "name": "" }))
            .await;
        assert_eq!(res.status_code(), 400);

        let body: serde_json::Value = res.json();
        assert_eq!(body["errors"]["name"][0]["code"], "length");
        assert_eq!(
            body["errors"]["name"][0]["message"],
            "name must be 1-50 characters"
        );
    })
    .await;
}

现在有三种错误 JSON：校验失败 {"errors":{…}}；Loco 自己的错误 {"error":"…","description":"…"}（409、坏 JSON 等）；scaffold 生成的 404 {"code":"not_found","message":…,"details":null}（第 5 课）。前两种是框架定的。第三种是 scaffold 自己写在 controller 里的 not_found()，想统一可以换成 Loco 的 Error::NotFound（练习 4）。
文档和 1.2.0 实际不一致处
  • Validate requests §4 说解析不了的输入“also returns 400”。实测缺字段 422、没带 Content-Type 415，只有 JSON 语法错才是 400。源码按 axum 的状态码返回；Error model reference 写的 “axum’s own rejection status (commonly 400/415/422)” 才准确。
  • 没有 ModelError::ModelValidation 这个名字。1.2.0 是 ModelError::Validation(ModelValidationErrors)，顶层还有 Error::Validation，两者都映射成 400 + {"errors":…}。
  • src/validation.rs 的模块注释示例：给 ActiveModel 实现 Validatable，在 before_save 里 self.validate()?。我照做后 POST {"name":"A"} 得到 500 {"error":"internal_server_error","description":"Internal Server Error"}。原因是错误被塞进 DbErr::Custom（into_db_error），1.2.0 没有任何地方把它还原成校验错误。字段信息只出现在服务端日志里。（试完已撤回。）

4. 练习

  1. 在你的 admin_api 里做 ②–⑤，贴回改造前后 {"name":""} 和 {"description":"no name"} 两个请求的状态码和响应体。
  2. 把 #[serde(default)] 去掉，重新请求 {"description":"no name"}，贴结果，用一句话解释为什么变了。然后加回来。
  3. 进阶（业务规则放 model）：分类名称不能重复。在 models\categories.rs 的 impl Entity 里写 ensure_name_unique(db, name, except_id)，重名时返回 ModelError::EntityAlreadyExists；create 和 update 里各调一次（update 要排除自己）。验证：重复 POST、把别的分类 PUT 成同名、把自己 PUT 成原名，贴三个结果；再给重复 POST 写一个断言 409 的 request 测试。
  4. 选做：把 controller 里 scaffold 生成的 not_found("category not found") 换成 Loco 的 Err(Error::NotFound)，请求一个不存在的 id，贴响应体，和原来的比一比。
  5. 间隔复习（第 5 课）：scaffold 生成的 update 对应哪个 HTTP 方法？发 PATCH 会怎样？
练习 3 参考答案（我在 playground 里实测过，先自己写再看）

src\models\categories.rs：

impl Entity {
    /// 业务规则：分类名称不能重复。更新时用 `except_id` 排除自己。
    pub async fn ensure_name_unique(
        db: &DatabaseConnection,
        name: &str,
        except_id: Option<i64>,
    ) -> ModelResult<()> {
        let mut query = Self::find().filter(categories::Column::Name.eq(name));
        if let Some(id) = except_id {
            query = query.filter(categories::Column::Id.ne(id));
        }
        if query.one(db).await?.is_some() {
            return Err(ModelError::EntityAlreadyExists);
        }
        Ok(())
    }
    // …第 5 课的 search 不变
}

controller：create 开头加 Entity::ensure_name_unique(&ctx.db, &params.name, None).await?;；update 在找到记录之后加 Entity::ensure_name_unique(&ctx.db, &params.name, Some(id)).await?;。ModelError 经 ? 变成 Error::Model，Loco 映射成 409（controller/mod.rs 第 267 行）。实测（已有 id 11 Toys）：
