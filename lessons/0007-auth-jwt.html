用内置 JWT auth 保护后台接口

目标：现在谁都能调 /api/categories 增删改。先把 Loco 自带的注册/登录流程走一遍，拿到 token；再给 categories 的 handler 加一个 auth::JWT 参数，不带 token 就 401。最后把第 6 课的测试改成带 token。

1. 先知道三件事

auth 是现成的，不用生成。loco new --db sqlite 生成的项目已经有 users 表、src\controllers\auth.rs 和 src\models\users.rs。路由前缀 /api/auth，跟本课有关的四个：

路由作用
POST /api/auth/register注册，生成邮箱验证 token，发欢迎邮件
GET /api/auth/verify/{token}用邮件里的 token 验证邮箱
POST /api/auth/login邮箱 + 密码换 JWT
GET /api/auth/current带 JWT 查“我是谁”

（另外还有 forgot、reset、magic-link、resend-verification-mail，本课不讲。cargo loco routes 能看到全部。）

auth::JWT 就是一个 axum 提取器。handler 参数里写上它，axum 在调用 handler 之前先执行它（controller/extractor/auth.rs 第 101 行）：

  1. 按配置 auth.jwt.location 找 token。不配就是请求头 Authorization: Bearer <token>（第 45 行 TOKEN_PREFIX = "Bearer "）。也可以配成 Cookie 或 Query 参数，或者写一个列表按顺序试（第 203 行 extract_token）。
  2. 用 auth.jwt.secret 校验签名和过期时间。算法 HS512，过期没有宽限（leeway = 0，auth/jwt.rs 第 132 行）。
  3. 成功 → handler 拿到 auth.claims；任何一步失败 → Error::Unauthorized → 401 {"error":"unauthorized","description":"You do not have permission to access this resource"}（controller/mod.rs 第 227 行）。具体原因只写进服务端日志，不告诉客户端。

token 里只有 pid 和 exp。UserClaims { pid: String, exp: u64, claims: Map }（auth/jwt.rs 第 43 行）。pid 是 users 表里的 UUID 列，不是自增 id。要拿到完整用户，自己查一次：users::Model::find_by_pid(&ctx.db, &auth.claims.pid)——内置的 /api/auth/current 就是这么写的。所以 auth::JWT 不查数据库，只验签名和过期（下面 ⑤ 会看到这意味着什么）。

2. 动手（在 playground\admin_api 真跑过）

PowerShell 写法，在 admin_api\ 根目录执行，cargo loco start 开着。我在 Linux 版 PowerShell 7 上跑，输出照实贴，token 截断显示。

① 注册：开发环境的邮件去哪了 
$api = "http://localhost:5150/api"
$body = @{ name = "Admin"; email = "admin@example.com"; password = "S3cret-pass" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "$api/auth/register" -ContentType "application/json" -Body $body | ConvertTo-Json -Compress
null

状态码 200，响应体就是 null（controller 里 format::json(())，() 序列化出来是 null）。不管邮箱是否已注册，都回一样的结果，免得别人用它探测哪些邮箱注册过。服务端日志里有两行 ERROR：

ERROR loco_rs::mailer: mailer error err="Error sending email (smtp): 'Connection error: Connection refused (os error 111)'"
ERROR loco_rs::bgworker: worker failed to perform job err="Error sending email (smtp): 'Connection error: Connection refused (os error 111)'"

原因：config\development.yaml 的 mailer.smtp 默认连 localhost:1025，本机没有 SMTP 服务。欢迎邮件是交给后台 worker 发的（开发环境 workers.mode: BackgroundAsync），所以发信失败不影响注册本身：用户已经写进数据库，email_verification_token 也生成了。想真的收到邮件，可以在 1025 端口跑一个本地邮件捕获工具（配置文件注释里提到 mailpit）；想连日志里的 ERROR 也不要，就在 mailer: 下加 stub: true（config\test.yaml 就是这么配的）。

$login = Invoke-RestMethod -Method Post -Uri "$api/auth/login" -ContentType "application/json" `

③ 带 token 调 /api/auth/current 
$headers = @{ Authorization = "Bearer $token" }
Invoke-RestMethod "$api/auth/current" -Headers $headers
pid                                  name  email
---                                  ----  -----
12e49e66-14b1-4c8e-88bf-db86f2d4685f Admin admin@example.com

不带 token、带一个乱写的 token、把 token 放到 ?token= 查询参数里（默认只看 Bearer 头），三种都是 401，响应体同上。token 中间那段只是 base64url 编码，不是加密，谁都能解开看：

$part = $token.Split('.')[1].Replace('-', '+').Replace('_', '/')
$part = $part.PadRight($part.Length + (4 - $part.Length % 4) % 4, '=')
[Text.Encoding]::UTF8.GetString([Convert]::FromBase64String($part))
{"pid":"12e49e66-14b1-4c8e-88bf-db86f2d4685f","exp":1793641790}

exp 是 Unix 时间戳，等于签发时刻 + auth.jwt.expiration（604800 秒 = 7 天）。头部是 {"typ":"JWT","alg":"HS512"}。所以别往 claims 里放机密信息。

④（可选）验证邮箱：没收到邮件，token 从哪拿

验证 token 只在邮件里和数据库里。没开邮件捕获的话，用 Loco 自带的 db seed --dump-tables 把 users 表导出成 YAML，找到它：

cargo loco db seed --dump-tables users --from tmp_dump
$hit = Select-String -Path tmp_dump\users.yaml -Pattern 'email: admin@example.com' -Context 0,2
$vtoken = ($hit.Context.PostContext[1] -split ': ')[1]
Remove-Item -Recurse tmp_dump      # 导出文件里有密码哈希，用完删掉
curl.exe -s -w " -> %{http_code}`n" "$api/auth/verify/$vtoken"
null -> 200
  • --from tmp_dump 指定导出目录。不指定的话会写进 src\fixtures\，覆盖第 4 课的 fixture。
  • 导出的键按字母排序，email 往下第 2 行就是 email_verification_token，所以 -Context 0,2 取 PostContext[1]。
  • 验证成功后 token 被清空（users::ActiveModel::verified 把它设成 None），同一个 token 再用一次就是 401，乱写的 token 也是 401。再登录一次，is_verified 变成 True。
⑤ 保护 /api/categories：src\controllers\categories.rs

每个 handler 加一个参数。只需要“已登录”的，用 _auth（前缀下划线表示不用它的值，只要它的检查）：

async fn list(
+   _auth: auth::JWT,
    State(ctx): State<AppContext>,
    Query(filter): Query<ListFilter>,
) -> Result<Response> {
// get_one、create、update 一样，各加一行 _auth: auth::JWT,

需要知道“是谁在操作”的，用 claims 里的 pid 查用户。以删除为例，顺手记一条日志：

use crate::models::{
    _entities::categories::{ActiveModel, Entity},
    users,
};

async fn remove(
    auth: auth::JWT,
    State(ctx): State<AppContext>,
    Path(id): Path<i64>,
) -> Result<Response> {
    // token 里只有 pid；要知道“是谁”，用 pid 查 users 表
    let user = users::Model::find_by_pid(&ctx.db, &auth.claims.pid).await?;
    let Some(model) = Entity::find_by_id(id).one(&ctx.db).await? else {
        return Ok(not_found("category not found"));
    };
    tracing::info!(category_id = id, by = %user.email, "category deleted");

    model.into_active_model().delete(&ctx.db).await?;

    Ok(StatusCode::NO_CONTENT.into_response())
}

auth 模块在 loco_rs::prelude::* 里，不用另外 use。这和 scaffold 不带 --no-auth 时生成的写法一样（第 5 课用了 --no-auth，现在手动补上）。cargo build、cargo loco start 之后：

curl.exe -s -w " -> %{http_code}`n" "$api/categories?page_size=2"
curl.exe -s -w " -> %{http_code}`n" -H "Authorization: Bearer $token" "$api/categories?page_size=2"
{"error":"unauthorized","description":"You do not have permission to access this resource"} -> 401
{"items":[{"id":1,"name":"Electronics & Gadgets","description":"Everything with a plug"},{"id":5,"name":"Books","description":null}],"page":1,"page_size":2,"total_pages":3,"total_items":5} -> 200

带 token 新建再删除：

$c = Invoke-RestMethod -Method Post -Uri "$api/categories" -Headers $headers -ContentType "application/json" -Body (@{ name = "Temp" } | ConvertTo-Json)
curl.exe -s -o NUL -w "%{http_code}`n" -X DELETE -H "Authorization: Bearer $token" "$api/categories/$($c.id)"
204

服务端日志：

INFO http-request: admin_api::controllers::categories: category deleted category_id=12 by=admin@example.com http.method=DELETE http.uri=/api/categories/12 …
用户被删了，token 还能用吗？我注册了一个临时用户，登录拿到 token，然后直接从数据库删掉这个用户，再用这个 token 请求：
  • GET /api/categories（只有 _auth: auth::JWT）→ 200。签名对、没过期就放行，不查库。
  • DELETE /api/categories/999 和 GET /api/auth/current（调了 find_by_pid）→ 404 {"error":"not_found","description":"Resource was not found"}。? 把 ModelError::EntityNotFound 映射成 404。
如果想要“用户不在了就 401”，用另一个提取器 auth::JWTWithUser<users::Model>：它会顺便按 pid 查用户，查不到返回 401（extractor/auth.rs 第 52–96 行），handler 里直接用 auth.user。
⑥ auth.jwt 配置：secret 和过期时间 
# config\development.yaml（生成时带了一个随机 secret，这里不贴）
auth:
  jwt:
    secret: <生成的随机串>
    expiration: 604800 # 7 days
    # location:            # 不写 = Authorization: Bearer
    #   from: Cookie       # Bearer / Cookie / Query；Cookie 和 Query 要写 name
    #   name: auth_token
  • expiration 单位是秒。改成 5 重启，登录后等 7 秒再请求，401，日志里是 JWT validation error: ExpiredSignature（我试完改回去了）。Loco 的登录只发一个 token，没有 refresh token，过期就重新登录。
  • secret 必须是合法的 base64：签名和验签都用 from_base64_secret（auth/jwt.rs 第 113、138 行）。
  • 三个环境的 secret 各不相同，test 里的不能拿去签 development 的 token。
  • 生产环境必须从环境变量读，不能提交到仓库里。谁拿到 secret 谁就能给任何 pid 签 token。配置文件是 Tera 模板，生成的 config\production.yaml 已经这样写： 
    auth:
  jwt:
    secret: <%= get_env(name="JWT_SECRET") %>
    expiration: 604800 # 7 days
    没写 default，变量没设就启动失败。我在生产配置下没设 JWT_SECRET（其他变量填了假值）跑 cargo loco doctor，报 environment variable `JWT_SECRET` not found and no `default` was given。PowerShell 7 里生成一个随机 base64 串并设置（仅当前窗口有效）： 
    $env:JWT_SECRET = [Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(48))
    （Windows PowerShell 5.1 没有这个静态 GetBytes 方法，用 PowerShell 7。）
⑦ 测试：第 6 课的测试现在全挂了

加上 auth 之后跑 cargo test，第 6 课的两个测试都失败了：它们没带 token，拿到的是 401。项目自带 tests\requests\prepare_data.rs：init_user_login(&request, &ctx) 注册并登录一个测试用户，返回带 token 的 LoggedInUser；auth_header(&token) 返回 Authorization: Bearer … 这对头。改成这样：

use super::prepare_data;

#[tokio::test]
#[serial]
async fn list_without_token_is_401() {
    request::<App, _, _>(|request, _ctx| async move {
        let res = request.get("/api/categories").await;
        assert_eq!(res.status_code(), 401);

        let body: serde_json::Value = res.json();
        assert_eq!(body["error"], "unauthorized");
    })
    .await;
}

#[tokio::test]
#[serial]
async fn create_rejects_empty_name_with_field_errors() {
    request::<App, _, _>(|request, ctx| async move {
        let user = prepare_data::init_user_login(&request, &ctx).await;
        let (key, value) = prepare_data::auth_header(&user.token);

        let res = request
            .post("/api/categories")
            .add_header(key, value)
            .json(&serde_json::json!({ "name": "" }))
            .await;
        assert_eq!(res.status_code(), 400);
        // …断言 errors.name 同第 6 课
    })
    .await;
}

注意三点：闭包参数从 _ctx 改成 ctx，因为 init_user_login 要用它查库；同一个测试里要发两次请求时，用 key.clone(), value.clone()；prepare_data 在 mod.rs 里是私有 mod，同级模块用 super::prepare_data 就能访问。playground 里一共 5 个：401、带 token 列表 200、400、409、删除 204 后再 GET 得 404。

cargo test --test mod requests::categories
test requests::categories::list_without_token_is_401 ... ok
test requests::categories::create_rejects_duplicate_name_with_409 ... ok
test requests::categories::list_with_token_is_200 ... ok
test requests::categories::create_rejects_empty_name_with_field_errors ... ok

全部测试：cargo test → 36 passed；cargo fmt --check 无输出。

DDD 视角：认证在边界，授权在领域。“你是谁”（验 token）是 HTTP 边界的事，交给提取器，handler 和 model 都不用管 token 长什么样。“你能做什么”（比如“只有管理员能删分类”）是业务规则，应该写成 model 里一个以用户为参数的方法，由 handler 调用，跟第 6 课的 ensure_name_unique 放在同一层。现在 users 表里没有角色字段，所以这条规则还没法写。
文档和 1.2.0 实际不一致处
  • Build a Small Authenticated App 说开发环境没有 SMTP 时注册会 500，要加 stub: true。实测（--bg async，即 BackgroundAsync）注册 200，邮件在后台 worker 里失败，只在日志里出现 ERROR。
  • 同一页说注册成功返回 {}；实测响应体是 null（format::json(())）。
  • 同一页 §7 保护自己资源的示例还是旧 scaffold 的写法（add handler、Json<Params>、params.update）。1.2.0 的 scaffold 默认就带 _auth: auth::JWT，handler 叫 create 等，参数是 DTO（第 5 课）。
  • 项目自带的 tests\requests\prepare_data.rs 里，init_user_login 用 POST /api/auth/verify + JSON 去验证邮箱。这个路由不存在（真正的是 GET /api/auth/verify/{token}），所以测试用户其实一直没验证。测试还能过，是因为登录不要求验证。auth.rs 里 “if the user not verified his email, he can't login” 这句注释也和代码对不上。
  • JWT auth 页写的 "<%= get_env(name='JWT_SECRET') %>"（单引号、外面加双引号），生成的 production.yaml 是不加引号、双引号参数。两种写法 Tera 都认。

4. 练习

  1. 在你的 admin_api 里走一遍 ①–③：贴回注册的结果、服务端日志里和邮件有关的那行、登录返回的 is_verified，以及 /api/auth/current 的输出。token 只贴前 20 个字符。
  2. 做 ⑤：给 categories 的五个 handler 加上 auth，贴不带 token 和带 token 请求列表的状态码。
  3. 做 ⑦：先不改测试直接 cargo test，贴失败那两行的 left/right；再改成带 token，贴通过结果。
  4. 进阶：把 get_one 的 _auth: auth::JWT 换成 auth: auth::JWTWithUser<users::Model>，在 handler 里 tracing::info! 打出 auth.user.email。请求一次，贴日志那一行。
  5. 选做：修好 prepare_data.rs 里那次错误的验证请求（改成 GET /api/auth/verify/{token}），再写一个测试断言登录返回的 is_verified 是 true。
  6. 间隔复习（第 6 课）：带 token POST {"description":"no name"} 会得到什么状态码？为什么不是 422？
