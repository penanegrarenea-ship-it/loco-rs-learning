axum → Loco 对照

Loco 1.2.0 基于 axum 0.8。每行都对照过 loco-rs 1.2.0 源码或生成项目；出处在表下。

Router

axumLoco
Router::new().route("/x", get(h))controller 里 Routes::new().add("/x", get(h))；也有 .get("/x", h)、.post(...) 等写法
Router::nest("/api/auth", ...)Routes::new().prefix("/api/auth")（另有 nest、merge）
在 main() 里把各模块 Router 合起来app.rs 的 Hooks::routes：AppRoutes::with_default_routes().add_route(controllers::auth::routes())
axum::serve(listener, app)Hooks::serve 默认实现替你做（into_make_service_with_connect_info::<SocketAddr>() + 优雅关闭）
现成的 axum Router 想原样用在 Hooks::after_routes 里返回/合并它（cargo loco routes 就看不到这些路由了）

框架内部最终做的就是：对每条路由 app.route(uri, method)，套中间件，然后 app.with_state(ctx)（src/controller/app_routes.rs 的 to_router）。

State

axumLoco
自己定义 #[derive(Clone)] struct AppState框架定义好的 AppContext（#[derive(Clone, FromRef)]，#[non_exhaustive]）
State(s): State<AppState>State(ctx): State<AppContext>
state 里放连接池、配置……8 个字段：environment db queue_provider config mailer storage cache shared_store
加自己的东西到 statectx.shared_store（在 Hooks::after_context 里放），handler 用 SharedStore 提取

Extractor 与返回值

axumLoco
Path、Query、Form、State、Multipart同一批，loco_rs::prelude::* 直接从 axum 重新导出
axum::Json<T>prelude 里的 Json<T> 是 Loco 包装（via(axum::Json)），解析失败转成 Loco 的 Error
自己写校验JsonValidate<T>、JsonValidateWithMessage<T>（基于 validator）
自己写鉴权 extractorauth::JWT（生成项目的 current handler 第一个参数就是它）
impl IntoResponse / Json(v)惯例返回 Result<Response>，用 format::json(v)；Result 是 loco_rs::Result。format::json 源码注释写明行为照搬 axum::Json：设 application/json，序列化失败回 500 纯文本
空响应 StatusCode::OKformat::empty()（生成器的默认返回）；纯文本 format::text("...")
Path/Query 解析失败 → 400 纯文本一样（就是 axum 的 extractor）。实测 ?limit=abc → 400 Failed to deserialize query string: limit: invalid digit found in string
路径占位符 /{id}（axum 0.8）一样：.add("stats/{section}", get(stats))
方法不匹配 → 405一样，实测带 allow: GET,HEAD
未匹配路由 → 默认 404 空体（或你设的 fallback）404，但响应体是 “Welcome to Loco!” HTML 页：默认开启的 fallback 中间件
#[debug_handler]prelude 里有，生成代码就在用

中间件

axumLoco
router.layer(TraceLayer::new()) 等手动挂默认一组中间件，在 config\*.yaml 的 server.middlewares 里开关；cargo loco middleware 查看
单个路由组 .layer(...)Routes::layer(...)，同样是 tower Layer
全局改中间件栈覆盖 Hooks::middlewares（默认 default_middleware_stack(ctx)）
.layer() 后加先执行（洋葱）一样是 LIFO，源码注释明确写了

默认启用（实测 cargo loco middleware）：limit_payload catch_panic etag logger request_id fallback powered_by；默认关闭：cors remote_ip compression timeout_request static secure_headers。
