命令速查：loco 与 cargo loco

版本：loco 1.2.0 / loco-rs 1.2.0（2026-09-22 发布）。下面每条命令都来自真实 --help 输出（2026-10-24，SQLite 项目 admin_api）。用 Postgres 或 --db none 的项目子命令会不同。

安装与生成器 loco

命令作用
cargo install loco装生成器（包名就叫 loco）
loco --version看版本 → loco 1.2.0
loco new [OPTIONS]生成新项目；loco 只有这一个子命令

loco new 参数

参数可选值 / 默认
-n, --name <NAME>项目名；不给就提问
--db <DB>sqlite | postgres | none
--bg <BG>async | queue-redis | queue-postgres | queue-sqlite | blocking
--assets <ASSETS>serverside | clientside | none
--embedded-assets静态资源打进二进制，仅 serverside
-p, --path <PATH>生成到哪个目录，默认 .
-a, --allow-in-git-repo在 git 仓库里生成时跳过确认
--os <OS>windows | linux | macos。--help 在 Linux 上显示默认 linux；按 CLI reference 和源码，在 Windows 上默认是 windows，会多生成 src\bin\tool.rs 和别名 cargo loco-tool（我用 --os windows 生成核对过）
-l, --log <LOG>生成器日志级别，默认 ERROR

没有 --template。--name --db --bg --assets 全给就完全不提问。我们用的：

loco new --name admin_api --db sqlite --bg async --assets none

项目里的 cargo loco

cargo loco = .cargo/config.toml 里的别名 loco = "run --"，跑的是项目自己的 <项目名>-cli。所有子命令都接受 -e, --environment <ENV>（默认 development）。

子命令作用常用参数（已核实）
start启动应用-p/--port、-b/--binding、-n/--no-banner、-w/--worker、-s/--server-and-worker、-a/--all、--scheduler
db数据库操作create migrate down [N] reset status entities truncate seed schema
routes以树形列出全部接口—
middleware列出中间件-c/--config 同时打印配置
task跑自定义任务[NAME] [key:val]...
jobs管理任务队列cancel tidy purge dump import retry requeue
scheduler跑 / 查看定时任务-l/--list、-n/--name、-t/--tag、-c/--config
generate代码生成（仅 debug 构建）model migration scaffold controller task scheduler worker mailer data deployment override
doctor检查配置和依赖-c/--config；-p/--production 已废弃，用 -e production
loco-tool（仅 --os windows 项目）.cargo\config.toml 里的别名 run --bin tool --，跑第二个二进制 tool，子命令同 cargo locoCHANGELOG 0.8.1：为 Windows 上“边运行边编译”而加
version打印应用版本实测输出 0.1.0 (dev)
watch改代码自动重启需另装 cargo-watch（据文档，未实测）

generate controller（第 3 课实测）

cargo loco generate controller <NAME> [ACTIONS]... [--auth]
cargo loco generate controller admin ping
added: "src/controllers/admin.rs"
injected: "src/controllers/mod.rs"
injected: "src/app.rs"
added: "tests/requests/admin.rs"
injected: "tests/requests/mod.rs"
  • 默认生成 index + 每个 action 一个 handler，都返回 format::empty()，全用 get。
  • 前缀会变复数：admin → .prefix("api/admins/")，需要的话手改。
  • 默认公开；--auth 给每个 handler 加 auth::JWT。
  • 在 app.rs 的 routes() 里自动加 .add_route(controllers::admin::routes())。

测试

cargo test --test mod requests::admin   # 集成测试只有一个目标：mod（tests\mod.rs）

官方 how-to 写的 cargo test --test requests_notes 在 1.2.0 生成的项目里不存在（实测报 no test target named ...）。

常用（第 1–3 课）

Windows 11 PowerShell 写法（我在 Linux 上验证，输出照实）：

cargo loco start                                  # 默认 http://localhost:5150
$env:PORT=5151; cargo loco start                  # 换端口（已实测）
Remove-Item Env:PORT                              # 用完清掉
cargo loco routes                                 # 列接口（树形）
cargo loco middleware                             # 列中间件，启用的在上
curl.exe http://localhost:5150/_ping              # {"ok":true}
curl.exe http://localhost:5150/_health            # {"ok":true}
curl.exe http://localhost:5150/_readiness         # {"ok":true}
curl.exe -s "http://localhost:5150/api/admin/stats/users?limit=2"   # 带 ? 的 URL 加引号
Invoke-RestMethod http://localhost:5150/_ping     # ok : True

在 PowerShell 里写 curl.exe 而不是 curl：Windows PowerShell 5.1 的 curl 是 Invoke-WebRequest 的别名。

cargo loco doctor 在新项目上会报 ❌ SeaORM CLI was not found，提示 cargo install sea-orm-cli。第 1 课不需要；官方教程把它列为安装步骤，用到 db entities 时再装。

出处：CLI reference、github.com/loco-rs/loco（src/cli.rs、loco-new/）。注意：文档 CLI reference 写生成项目的 loco-rs 版本要求“currently 1.1”，源码 loco-new/src/lib.rs 已是 "1.2"，生成的 Cargo.toml 实际为 loco-rs = { version = "1.2" }。
