命令速查：loco 与 cargo loco

版本：loco 1.2.0 / loco-rs 1.2.0（2026-09-22 发布）。下面每条命令都来自真实 --help 输出（2026-10-24，SQLite 项目 admin_api）。用 Postgres 或 --db none 的项目子命令会不同。

安装与生成器 loco

命令作用
cargo install loco装生成器（包名就叫 loco）
loco --version看版本 → loco 1.2.0
loco new [OPTIONS]生成新项目；loco 只有这一个子命令

loco new 参数

参数可选值 / 默认
-n, --name <NAME>项目名；不给就提问
--db <DB>sqlite | postgres | none
--bg <BG>async | queue-redis | queue-postgres | queue-sqlite | blocking
--assets <ASSETS>serverside | clientside | none
--embedded-assets静态资源打进二进制，仅 serverside
-p, --path <PATH>生成到哪个目录，默认 .
-a, --allow-in-git-repo在 git 仓库里生成时跳过确认
--os <OS>windows | linux | macos。--help 在 Linux 上显示默认 linux；按 CLI reference 和源码，在 Windows 上默认是 windows，会多生成 src\bin\tool.rs 和别名 cargo loco-tool（我用 --os windows 生成核对过）
-l, --log <LOG>生成器日志级别，默认 ERROR

没有 --template。--name --db --bg --assets 全给就完全不提问。我们用的：

loco new --name admin_api --db sqlite --bg async --assets none

项目里的 cargo loco

cargo loco = .cargo/config.toml 里的别名 loco = "run --"，跑的是项目自己的 <项目名>-cli。所有子命令都接受 -e, --environment <ENV>（默认 development）。

子命令作用常用参数（已核实）
start启动应用-p/--port、-b/--binding、-n/--no-banner、-w/--worker、-s/--server-and-worker、-a/--all、--scheduler
db数据库操作create migrate down [N] reset status entities truncate seed schema
routes以树形列出全部接口—
middleware列出中间件-c/--config 同时打印配置
task跑自定义任务[NAME] [key:val]...
jobs管理任务队列cancel tidy purge dump import retry requeue
scheduler跑 / 查看定时任务-l/--list、-n/--name、-t/--tag、-c/--config
generate代码生成（仅 debug 构建）model migration scaffold controller task scheduler worker mailer data deployment override
doctor检查配置和依赖-c/--config；-p/--production 已废弃，用 -e production
loco-tool（仅 --os windows 项目）.cargo\config.toml 里的别名 run --bin tool --，跑第二个二进制 tool，子命令同 cargo locoCHANGELOG 0.8.1：为 Windows 上“边运行边编译”而加
version打印应用版本实测输出 0.1.0 (dev)
watch改代码自动重启需另装 cargo-watch（据文档，未实测）

generate controller（第 3 课实测）

cargo loco generate controller <NAME> [ACTIONS]... [--auth]
cargo loco generate controller admin ping
added: "src/controllers/admin.rs"
injected: "src/controllers/mod.rs"
injected: "src/app.rs"
added: "tests/requests/admin.rs"
injected: "tests/requests/mod.rs"
  • 默认生成 index + 每个 action 一个 handler，都返回 format::empty()，全用 get。
  • 前缀会变复数：admin → .prefix("api/admins/")，需要的话手改。
  • 默认公开；--auth 给每个 handler 加 auth::JWT。
  • 在 app.rs 的 routes() 里自动加 .add_route(controllers::admin::routes())。

generate model 与 db（第 4 课实测）

cargo install sea-orm-cli                         # db entities 要用；没装时 generate model 停在一半
cargo loco generate model product name:string! price:int status:string
cargo loco db status                              # 每个 migration：Applied / Pending
cargo loco db migrate                             # 执行所有 Pending 的 up
cargo loco db down                                # 回滚最近 1 个，执行它的 down()
cargo loco db down 2                              # 回滚最近 2 个
cargo loco db reset                               # 删所有表 → 重跑全部 migration（不 seed）
cargo loco db truncate                            # 调 Hooks::truncate，清数据不删表
cargo loco db entities                            # 按当前数据库重写 src\models\_entities\
cargo loco db seed --reset                        # 删表 → 重跑 migration → 读 src\fixtures\*.yaml
cargo test --test mod models::products
cargo loco generate migration AddSkuToProducts sku:string   # 只写文件，不自动执行
cargo loco db migrate; cargo loco db entities                # 再手动这两步
added: "migration/src/m20261025_124100_products.rs"
injected: "migration/src/lib.rs"
injected: "migration/src/lib.rs"
added: "tests/models/products.rs"
injected: "tests/models/mod.rs"
  • generate model 已自动跑了 db migrate 和 db entities；结尾那句 “You can now apply it with …” 不用照做。
  • 字段：无后缀 = 可空（Option），! = NOT NULL，^ = 唯一；int → i64。--without-tz 不要 created_at/updated_at。
  • _entities\ 每次整个重写，别手改；models\<name>.rs 只生成一次，代码写这里。
  • 生成器会对整个项目跑 cargo fmt：生成前先 git commit。
  • seed 要自己在 app.rs 的 Hooks::seed / truncate 里加一行。不带 --reset 重复 seed 会报 UNIQUE constraint failed。
  • 开发环境 config\development.yaml 里 auto_migrate: true：cargo loco start 启动时会自动跑 Pending 的 migration。cargo loco db ... 子命令不受它影响。
  • 没有 db up / db fresh 子命令。
  • db truncate 只清 Hooks::truncate 里列出的表；db seed --reset 是删表重建，不是 truncate。
  • 只在数据库里手动改表、不写 migration：db entities 会照着生成字段，但下次 db reset 或 seed --reset 就没了，seed 和查询都会报 no such column。

generate scaffold（第 5 课实测）

cargo loco generate scaffold category name:string! description:text --no-auth
added: "migration/src/m20261025_134358_categories.rs"      ┐
injected: "migration/src/lib.rs"（×2）                      │ 同 generate model
added: "tests/models/categories.rs"                        │（并已自动 migrate + entities）
injected: "tests/models/mod.rs"                            ┘
added: "src/controllers/categories.rs"
injected: "src/controllers/mod.rs"
injected: "src/app.rs"
added: "src/dtos/categories.rs"
injected: "src/dtos/mod.rs"
HTTP路径handler成功
GET/api/categories?page=&page_size=list200 分页信封（默认 25 条/页）
POST/api/categoriescreate201
GET/api/categories/{id}get_one200；不存在 404 {"code":"not_found",…}
PUT/api/categories/{id}update200（全字段）
DELETE/api/categories/{id}remove204
  • 1.2.0 只有 --without-tz、--no-auth。--api 是隐藏的空操作，--html/--htmx 报错；有 frontend\ 时自动多生成 React 页面。
  • 不加 --no-auth：每个 handler 带 auth::JWT，匿名请求 401。
  • 没有 PATCH（405）、没有校验、没有接口测试（只有 model 测试）；controller 直接用 _entities，业务规则要自己挪进 models\<name>.rs。
# PowerShell 发 JSON：哈希表 + ConvertTo-Json，记得 -ContentType（不带回 415）
$base = "http://localhost:5150/api/categories"
Invoke-RestMethod -Method Post -Uri $base -ContentType "application/json" -Body (@{ name = "Books" } | ConvertTo-Json)
Invoke-RestMethod -Method Put  -Uri "$base/1" -ContentType "application/json" -Body (@{ name = "X"; description = "Y" } | ConvertTo-Json)
Invoke-RestMethod -Method Delete "$base/1"
Invoke-RestMethod "$($base)?page=2&page_size=2"
# curl.exe：JSON 先写文件，再 --data-binary "@文件"
Set-Content -Path body.json -Value '{"name":"Books"}'
curl.exe -s -i -X POST -H "Content-Type: application/json" --data-binary "@body.json" $base
# Invoke-RestMethod 遇 4xx 抛异常：
try { Invoke-RestMethod "$base/999" } catch { $_.Exception.Response.StatusCode.value__; $_.ErrorDetails.Message }

try { Invoke-RestMethod -Method Post -Uri $base -ContentType "application/json" -Body (@{ name = "" } | ConvertTo-Json) }

常用（第 1–6 课）

Windows 11 PowerShell 写法（我在 Linux 上验证，输出照实）：

cargo loco start                                  # 默认 http://localhost:5150
$env:PORT=5151; cargo loco start                  # 换端口（已实测）
Remove-Item Env:PORT                              # 用完清掉
cargo loco routes                                 # 列接口（树形）
cargo loco middleware                             # 列中间件，启用的在上
curl.exe http://localhost:5150/_ping              # {"ok":true}
curl.exe http://localhost:5150/_health            # {"ok":true}
curl.exe http://localhost:5150/_readiness         # {"ok":true}
curl.exe -s "http://localhost:5150/api/admin/stats/users?limit=2"   # 带 ? 的 URL 加引号
Invoke-RestMethod http://localhost:5150/_ping     # ok : True
Invoke-RestMethod http://localhost:5150/api/admin/products | Format-Table id, name, price, status

在 PowerShell 里写 curl.exe 而不是 curl：Windows PowerShell 5.1 的 curl 是 Invoke-WebRequest 的别名。

cargo loco doctor 在新项目上会报 ❌ SeaORM CLI was not found，提示 cargo install sea-orm-cli。官方教程把它列为安装步骤；第 4 课 generate model 起必须装。

出处：CLI reference、github.com/loco-rs/loco（src/cli.rs、loco-new/）。注意：文档 CLI reference 写生成项目的 loco-rs 版本要求“currently 1.1”，源码 loco-new/src/lib.rs 已是 "1.2"，生成的 Cargo.toml 实际为 loco-rs = { version = "1.2" }。
