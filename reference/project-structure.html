项目结构图

依据：真实生成的项目 loco new --name admin_api --db sqlite --bg async --assets none（loco 1.2.0，2026-10-24）。注释来自文件实际内容和官方文档。Windows 路径分隔符是 \。

admin_api\
├─ Cargo.toml              依赖：loco-rs 1.2、axum 0.8、sea-orm 2.0……；二进制 admin_api-cli
├─ .cargo\config.toml      别名 loco = "run --"（cargo loco 的来源）；Windows MSVC 目标用 rust-lld 链接
├─ config\
│  ├─ development.yaml     端口(PORT,默认5150)、数据库、日志、中间件开关、JWT 密钥
│  ├─ test.yaml            cargo test 用
│  └─ production.yaml      生产；密钥全从环境变量读
├─ migration\              独立 crate：数据库迁移
│  └─ src\
│     ├─ lib.rs            Migrator，迁移列表（inject-above 注释别删，生成器靠它插入）
│     └─ m20220101_000001_users.rs   建 users 表
├─ src\
│  ├─ bin\main.rs          cli::main::<App, Migrator>() —— 唯一入口
│  ├─ bin\tool.rs          【仅 --os windows】第二个二进制，内容同 main.rs
│  ├─ lib.rs               声明下面各模块
│  ├─ app.rs               ★ impl Hooks for App：routes / connect_workers / register_tasks / truncate / seed / initializers
│  ├─ controllers\
│  │  ├─ mod.rs            pub mod auth;
│  │  └─ auth.rs           9 个 /api/auth/* handler + pub fn routes()
│  ├─ models\
│  │  ├─ _entities\        Sea-ORM 实体，按表结构生成，别手改（users.rs、prelude.rs）
│  │  └─ users.rs          ★ 业务方法：find_by_email、create_with_password、verify_password、generate_jwt……

├─ tests\

├─ .github\workflows\ci.yaml
└─ （运行后）target\  Cargo.lock  admin_api_development.sqlite

请求的路线

config\*.yaml（中间件开关）→ app.rs 的 routes() → controllers\xxx.rs 的 handler → models\xxx.rs 的方法（用 models\_entities 访问数据库）→ 用 views\ 或 dtos\ 里的结构体 format::json(...) 返回。

DDD 粗对应（建议，非官方约定）

目录大致对应
controllers\接口层
models\<name>.rs领域层（Active Record：同时管持久化）
models\_entities\、migration\基础设施层
workers\、tasks\、mailers\应用层 / 基础设施之间
views\、dtos\接口层的数据传输对象

官方立场：领域逻辑写在 model 上，不加 services/、repositories/（Loco doctrine）。
